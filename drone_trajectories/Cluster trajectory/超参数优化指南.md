# 🎯 集群轨迹模型超参数优化完整指南

## 📊 当前问题诊断

你的模型在 **epoch 57** 就触发早停，说明存在以下问题：

| 症状 | 原因 | 解决方案 |
|------|------|--------|
| 早停太快（<100 epochs） | 学习率过高 / 学习退化 | 降低学习率或使用 warmup |
| 验证损失停滞（0.124） | 模型容量不足 / 正则化过强 | 增大模型 / 降低 dropout |
| 训练损失继续下降 | 过度拟合 | 增加正则化 |

### 当前参数问题分析

```python
patience=50           # ⚠️ 太大！会浪费 50 个 epoch 看无改进
learning_rate=1e-3    # ⚠️ 可能过高，导致梯度不稳定
dropout=0.5           # ⚠️ 太强！可能阻止模型学习复杂模式
weight_decay=1e-5     # ⚠️ 太弱，正则化不足
```

## 📈 关键超参数解释

### 1. **学习率 (lr)** 🎯 最重要
```
1e-3  → 太高，损失震荡，早停
5e-4  → 中等，可能不稳定
1e-4  → 稳定，收敛慢，容易找到好的最小值
```

**建议：** 从 `2e-4` 开始，如果验证损失波动大则降到 `1e-4`

### 2. **Dropout** 🛡️ 防过拟合
```
0.1   → 几乎无正则化，易过拟合
0.3   → 平衡，推荐
0.5+  → 强正则化，可能欠拟合
```

**建议：** 从 `0.3` 开始，监控训练/验证损失差距

### 3. **Batch Size** 📦 训练稳定性
```
128   → 小批次，梯度噪声大，但精度高
256   → 中等，平衡
512   → 大批次，梯度平滑，但容易陷入局部最小值
```

**建议：** 从 `256` 开始，根据显存调整

### 4. **Patience** ⏱️ 早停耐心
```
10    → 太短，可能停不在最优点
25-50 → 适中，给模型搜索空间
100   → 太长，浪费时间
```

**建议：** `patience = min(total_epochs // 5, 30)`

### 5. **Teacher Forcing Ratio** 👨‍🏫 序列学习
```
0.5   → 50% 真实 + 50% 预测
0.7   → 70% 真实，更稳定，学得更好
0.9   → 90% 真实，像有监督学习
```

**建议：** 从 `0.6` 开始，更高的比例通常更好

## 🔍 诊断和调试技巧

```bash
# 打开 CSV 文件查看详细训练过程

# 关键指标：
# - Train Loss：持续下降 → 正常
# - Val Loss：在某个点后停滞 → 可能已收敛
# - MAE：最终值应 < 0.15m
```

### 🎯 如何判断是否找到"最好"的模型

| 指标 | 优秀 | 一般 | 差 |
|------|------|------|-----|
| **MAE (m)** | < 0.10 | 0.10-0.15 | > 0.20 |
| **收敛 epoch** | 50-150 | 150-300 | > 300 |
| **Val Loss** | 0.08-0.12 | 0.12-0.20 | > 0.25 |
| **Train/Val 差** | < 0.02 | 0.02-0.05 | > 0.10 |

### ⚠️ 常见问题和解决方案

**问题 1: 训练损失始终无法下降**
```
原因：学习率太低 / 模型容量不足
解决：增加 lr 到 5e-4，或增加 hidden_size 到 256
```

**问题 2: 验证损失震荡很大**
```
原因：学习率太高 / batch_size 太小
解决：降低 lr 到 1e-4，增加 batch_size 到 512
```

**问题 3: 模型很快就停止改进（epoch < 50）**
```
原因：正则化过强 / 学习率不适合
解决：降低 dropout 到 0.2，降低 weight_decay 到 1e-5
```

**问题 4: 训练很快但验证损失很高**
```
原因：过拟合
解决：增加 dropout 到 0.4，增加 weight_decay 到 1e-4
```
